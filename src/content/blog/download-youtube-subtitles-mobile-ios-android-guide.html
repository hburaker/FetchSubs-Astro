You can download YouTube subtitles on a phone without installing anything: copy the video link from the YouTube app, paste it into FetchSubs in your mobile browser, tap Download, then tap SRT, VTT or TXT next to the language you want. On an iPhone the file goes to the Downloads folder in the Files app; on Android it goes wherever Chrome saves downloads, which you can reach from Chrome's Downloads list or the Files app.

That's the whole process. The rest of this post goes through each step on both systems, explains which button to tap for what you're doing, and covers the few things that can go wrong on a phone.

Step 1: Copy the video link

In the YouTube app, open the video, tap Share under the player and choose Copy link. If you're watching in a browser instead, copy the address from the address bar.

The link the app copies is usually a short youtu.be address with a ?si= code on the end. You don't need to clean that up. While updating this post I pasted a youtu.be link with the ?si= part still attached, and an m.youtube.com link from a mobile browser; FetchSubs found the right video both times. Shorts links work too (more on those on the Shorts transcript page).

Step 2: Paste it into FetchSubs

Open fetchsubs.com in Safari, Chrome or whatever browser you use. Tap the box that says Paste a YouTube link, long-press, choose Paste, then tap Download.

After a few seconds a card appears with the video's thumbnail, title, channel and length, and under it a list headed Available Subtitle Tracks. Each row is one caption track: the language name, a label saying (Official) for captions the creator uploaded or (Auto-generated) for YouTube's speech recognition, and four buttons: SRT, VTT, TXT and RAW.

If the same language appears twice, one official and one auto-generated, pick the official one. It was written or checked by a person, and the auto-generated one usually has no punctuation and more mistakes with names.

If the track list comes up empty, the video has no captions at all. FetchSubs downloads caption tracks that already exist on YouTube; it doesn't create captions from the audio. The transcript not available post lists the usual reasons.

Step 3: Choose the button that fits what you're doing

On a phone the choice matters a bit more than on a computer, because files are more awkward to deal with.

  • RAW opens the plain text in a new browser tab. Nothing is saved to the phone. For reading a transcript, or copying it into a notes app or an AI chat, this is usually the easiest option: open RAW, long-press the text, Select All, Copy.
  • TXT saves the same text as a file. Choose it if you want to keep the transcript or send it to someone.
  • SRT saves the captions with their timestamps. You need this if the captions are going into a video editing app or onto another video.
  • VTT is the web version of SRT. On a phone you rarely need it, unless you're preparing captions for a website.

The file name is built from the video title and the language code, for example Me_at_the_zoo_en.srt. Auto-generated tracks get _auto before the extension, so you can tell them apart in the Downloads folder.

Where the file goes on iPhone and iPad

Safari saves downloads to the Downloads folder in the Files app. Open Files, tap Browse and look for Downloads. By default that folder sits in iCloud Drive; you can switch it to on-device storage in Safari's Downloads setting in the Settings app. Apple's page Where to find downloads on your iPhone or iPad has the current steps. Safari may ask whether you want to download the file first; if it does, tap Download.

A TXT file opens in a preview straight from Files. SRT and VTT files are plain text as well, but iOS doesn't always know which app should open them, so use the Share button to send them on to a text editor, the Notes app or the editing app you're working in.

Where the file goes on Android

Chrome saves the file to your default download location, which on most phones is the Downloads folder. To find it, open Chrome, tap the three-dot More menu and choose Downloads, or open your phone's Files app. Google's help page on downloading files in Chrome for Android has the details. Other browsers have their own downloads list, and phone makers ship different file manager apps, so the exact screens vary.

Tapping an SRT or TXT file asks you which app to open it with. Any text editor will do. If you want to edit a long transcript properly, a word processor such as Google Docs is more comfortable than a basic editor.

If something doesn't work

RAW does nothing. RAW opens a new tab, and some mobile browsers treat that as a pop-up. If nothing appears, check whether the browser blocked a pop-up and allow it for fetchsubs.com, or use TXT instead.

The download doesn't appear. Look in the browser's own downloads list first, then in the Files app. If it isn't in either, try once more in a normal (not private) tab, and make sure the phone isn't out of storage.

The text looks garbled. The files are UTF-8 text. Current apps read that correctly; if an older app shows strange characters in place of accented letters, look for an encoding option and set it to UTF-8.

You only want to read along. Then you may not need FetchSubs at all. The YouTube app can show a transcript panel from the video description (YouTube Help: View video transcripts). FetchSubs is for when you want the text outside YouTube, as a file or as text you can copy.

What a phone is and isn't good for here

Grabbing a transcript to read later, pasting it into a chat app, or saving the SRT for a mobile video editor all work well on a phone. Fixing a lot of caption errors doesn't. Editing hundreds of timed blocks on a small screen is slow, and if an auto-generated track needs real cleanup I'd send the SRT to a computer and do it there. The post on fixing subtitle timing covers that part.

FetchSubs handles one video at a time and doesn't keep the links you paste or the files you download, so there is no history to come back to. If you'll need the transcript again, save the file.
